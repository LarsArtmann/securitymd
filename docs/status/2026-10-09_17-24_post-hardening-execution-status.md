## d) TOTALLY FUCKED UP

1. **The critical-gate bug was a shipped, green, "verified" defect.** The severity-override feature (prior session, concurrent session) added `--set-severity rule=critical` while `hasErrors` used equality semantics — so the STRONGEST escalation a user can configure silently passed CI. Every prior "all gates green" claim was true and insufficient at the same time: the tests never expressed the expectation "critical must fail the build." The prior report even listed "suppression×severity interaction untested" as a known gap — the honest note was there, the test wasn't. Lesson (repeated from e.6 of the last report): **a known-gap note is not a mitigation; only a test is.**
2. **Nothing else in this session's scope broke** — but d.1 is exactly the kind of fuckup that hides behind green dashboards, so it gets the section to itself. If there is a second-order fuckup, it is this: I shipped the drift guard _because_ docs lied about exit codes, and the guard itself initially shipped without a red-run demonstration (b.3) — the fix for "unverified claims" was itself partially unverified.

## e) WHAT WE SHOULD IMPROVE

1. **Negative-test-first, enforced by checklist.** Twice in a row now (docs-gate last session, drift guard this session) the red-run proof came after the green run — or not at all. Cheap fix: before declaring any guard "done", mutate the target in a throwaway copy and watch it fail.
2. **Stale-read dance with the daemon.** Three edit refusals this session from "file modified since read" (daemon auto-commits bump mtimes mid-edit). Should re-View immediately after any daemon-commit notice instead of retrying from memory; the concurrent-session protocol already prescribes this — I applied it to the other session, not to the daemon.
3. **Linter-tax drafting repeats.** Undefined `strings` import, func-value-vs-string mismatch in the acceptance specs, gofumpt/golines rounds — same lesson as prior report e.4. A mental pre-pass against the known config (wsl cuddles, gci grouping, golines ≈120) would save one cycle per file.
4. **Contract-test fixture sentinels are cleverly opaque.** `"fixture:compliant.md"` / `"fixture-suppressed:all"` strings decoded in a switch are harder to read than a plain table column with the content resolver named. Works, pinned, but the next reader pays.
5. **Sweep script honesty gap**: `buildflow -s securitymd` (detect) exits 0 even when findings exist — the script's classification rests entirely on file presence, which is correct but should be documented in the script header so nobody trusts buildflow's exit code there.
6. **cmd/ is lint-excluded**, so the contract test (now the most safety-critical test in the repo) runs outside the 0-issue bar. Quality there is purely self-imposed. Consider narrowing the exclusion to `cmd/**` non-test files, or accepting and documenting the risk (current choice).
7. **Cross-package fixture path** (`test/acceptance` → `../../pkg/policy/testdata/`) is intentional single-sourcing but silently breaks if either tree moves; the `require.NoError` message names the path, which is the mitigation. Fine — worth knowing.
8. **Per-package coverage visibility**: repo-total is 87.6% but cmd/securitymd sits at 77.6%. The gate is total-only; if cmd grows, it can decay invisibly while the gate stays green.
